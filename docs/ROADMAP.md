# 道のり

## 優先順位（2026-10-03 見直し）

- 題材・検品・学び（頭身や顔立ちの基準）の中心は 10 代〜20 代、特に高校生〜大学生。次に 20 代〜30 前後。一桁・30 代・40 代は家族として少し、高齢は重要人物として少数、男性は後回し（2026-10-17、利用者の開発方針）

目的は、Claude に「○○なキャラクターを作って」と頼めば、綺麗なキャラクターデザインが出て、
デザインはイラストで決め、そこから後の加工（デフォルメ・ちびキャラ、ドット絵、3D、リアル風）に繋げられること。
リアル風は加工の1つとして最後に置き、優先度を最も低くする。

1. ベース: 文章 → 綺麗なキャラクターデザインの絵（画像生成。`tools/gen/design.py draw`）
2. 同じ人物を保つ: 正面・横・後ろ、表情、ポーズを同じ人物のまま描き分ける
3. 後の加工（イラストから作るオプション）: デフォルメ・ちびキャラ、ドット絵（`pixel`）、3D（Blender。人物の比率と服を絵に合わせる）、リアル風（`restyle --style real`。優先度は最低）
   - ドット絵の作風: 等身を保つ少ない色の見下ろしアクション（`pixel --preset survivor`、使える水準）と、箱庭ドット（頭を大きくする変換が要る）
4. 作風に寄せる: 派生のドット絵を、手本の全コマの分布（`tools/learn.py`）に近づける。箱庭ドットの頭身への変換

5. 亜人の設定資料の道具（`tools/gen/demi.py`）を、手元で動くアプリにする。計画は `docs/app/PLAN.md`（長期開発で進める）

## 0.5 生成の質と速さの基準（2026-10-12）

基準は外部の画像生成（Figma の generate_image、gpt-image-2.5-sunburst）で同じ頼みを描いた絵。頼んだ持ち物・構図・インナーカラーが通り、
顔の形のずれ 0.062、1 枚 1024x1536 が数十秒で出る。手元（Animagine、CPU）は 832x1216 が約 5 分、4K までで約 16 分で、持ち物と構図が崩れた。
- 質: 外部の生成と同じ頼みで描き比べ、作画監督の判定と数字（measure.py）で並ぶか超えるかを見る
- 速さ: 1 枚目が見えるまでの時間で比べる。手元の CPU では埋まらないので、描く役は外部の生成に差し替えられる形にし、検品と学習は手元で行う
- 外部の生成で描いた絵も同じ検品と学習（measure・feedback）に掛ける

## 0.7 デッサン人形（Drawing-mannequin）は道具として参考にする

人形のリポジトリは利用者が手で開発する。こちらから作業を頼んだり、定期実行を回したりしない。
こちらはポーズの決め方（骨格・関節・ポーズ集）を道具として参考にし、使える形になっていれば下絵に取り込むかを判断する。

- 検品の候補（まだ数字にしていない崩れ）: 靴の左右の色・形の食い違い。部位分けの左右の靴の平均色では、灰色の片方が混じっても差が 6〜8 しか出ず、剣や脚を靴に含めた（16,621 画素）。足元を切り出して左右を別に読む方法が要る
- 検品の候補: 服の部位ごとの色が設定の色と合うか（紺のコートが 4 枚中 4 枚で灰・茶・生成り・薄茶になった）
- 検品の候補の測り直し（2026-10-17）: 目の開き（高さ ÷ 幅）は半目の絵 0.37 と開いた目の絵 0.31 で分けられなかった（目の塊がまつ毛を含む）。脚の交差（足首と股の左右の入れ替わり）は 26 枚で 0 件、利用者が挙げた「付け根の読めない脚」は入れ替わりではなく重なりだった。靴の左右の色の差は、違う靴の絵で 35.5、そろった絵で 2〜6 だが、影や裾で 15〜30 も出るので目で確かめる印に留めている
