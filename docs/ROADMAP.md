# 道のり

## 優先順位（2026-10-03 見直し）

目的は、Claude に「○○なキャラクターを作って」と頼めば、綺麗なキャラクターデザインが出て、
デザインはイラストで決め、そこから後の加工（デフォルメ・ちびキャラ、ドット絵、3D、リアル風）に繋げられること。
リアル風は加工の1つとして最後に置き、優先度を最も低くする。

1. ベース: 文章 → 綺麗なキャラクターデザインの絵（画像生成。`tools/gen/design.py draw`）
2. 同じ人物を保つ: 正面・横・後ろ、表情、ポーズを同じ人物のまま描き分ける
3. 後の加工（イラストから作るオプション）: デフォルメ・ちびキャラ、ドット絵（`pixel`）、3D（Blender。人物の比率と服を絵に合わせる）、リアル風（`restyle --style real`。優先度は最低）
   - ドット絵の作風: 等身を保つ少ない色の見下ろしアクション（`pixel --preset survivor`、使える水準）と、箱庭ドット（頭を大きくする変換が要る）
4. 作風に寄せる: 派生のドット絵を、手本の全コマの分布（`tools/learn.py`）に近づける。箱庭ドットの頭身への変換

5. 亜人の設定資料の道具（`tools/gen/demi.py`）を、手元で動くアプリにする。計画は `docs/app/PLAN.md`（長期開発で進める）

## 0.5 生成の質と速さの基準（2026-10-12）

基準は外部の画像生成（Figma の generate_image、gpt-image-2.5-sunburst）で同じ頼みを描いた絵。頼んだ持ち物・構図・インナーカラーが通り、
顔の形のずれ 0.062、1 枚 1024x1536 が数十秒で出る。手元（Animagine、CPU）は 832x1216 が約 5 分、4K までで約 16 分で、持ち物と構図が崩れた。
- 質: 外部の生成と同じ頼みで描き比べ、作画監督の判定と数字（measure.py）で並ぶか超えるかを見る
- 速さ: 1 枚目が見えるまでの時間で比べる。手元の CPU では埋まらないので、描く役は外部の生成に差し替えられる形にし、検品と学習は手元で行う
- 外部の生成で描いた絵も同じ検品と学習（measure・feedback）に掛ける

## 0.55 作画監督の数字の検品（最も重要。2026-10-12）

測り方は `tools/gen/measure.py`、基準は `styles/anime-norms.json`、学習は `tools/gen/normlearn.py`。
基準は答えの分かっている絵（3D の素体、わざと崩した絵）で較正してから使う。

1. [x] 顔の形（頭の型を当てはめ、正面に戻すと歪む量）
2. [x] 影の順序（人物の中で、光に背を向けた面が明るい部位）
3. [x] 髪の白飛びと、指定の色からの外れ
4. [x] 背景の光と人物の照らされ方の食い違い（scene.backlit_front。逆光の場面で顔が正面から明るい）（背景は逆光なのに人物の前面が正面から明るい。外部の生成で見逃した）
5. [~] 左右の対の食い違い（片手が籠手で片手が素手、左右の靴の形が違う）。色の差は測る（pairs）。境は判定と指摘が溜まったら学ぶ。面積と形は部位分けが左右を取り違えるので、別の取り方が要る
   - 2026-10-13: 全身の絵 24 枚で靴の色の差を測ると、目で見て左右がそろった靴で 0.017〜0.451（同じ茶色のブーツで 0.248、白い靴で 0.451）、左右で違う靴で 0.06 と 0.183 になり、分けられなかった。部位分けの左右の靴の範囲そのものが当てにならない。靴は足首より下を、人物の左右の半分で切って比べるなど、取り方から作り直す。左右の靴の部位を合わせて塊で 2 つに分ける試作も、24 枚中 11 枚で靴が1つの塊になり、そろったブーツで 0.325 と出て分けられなかった
6. [x] 髪の指定色を2色以上（地の色とインナーカラー）持てるようにする（--hair "#1e1a24,#a8203c"）
   - [ ] 色相だけで近さを見ているので、光で桃色に染まった黒髪が深紅のインナーカラーに近いとして通る。明るさと彩度の近さも比べる
     - 2026-10-13: 明るさと彩度でも分けられなかった。暖色の光の下の黒髪と深紅のインナーカラーは、赤寄りの画素の彩度の中央値が 0.46 と 0.39、明るさも重なる。色だけでなく、どの髪の束に色があるか（内側の束か、光の当たる外側か）で分ける必要がある
7. [ ] ポーズの硬さ（数字にない指摘として残った）
8. [ ] 崩れの手本を増やす（素体の目・口をわざとずらした絵で、どこまで小さな歪みを見つけられるかを測る）
   - 2026-10-13: 全身の騎士の片目を 2〜8 画素（両目の間隔の 6〜25%）上へずらしても、顔の形のずれは変わらなかった（頭の傾きとして吸収される）。片目の高さのずれは、頭の傾きを顔の輪郭やあごから別に決めて測る必要がある
9. [x] 逆光なのに顔の真ん中に出る白い光の点（scene.backlit_spot）と、それを周りの肌で埋める処理（imgproc.spot_fill）
10. [x] 小さい顔の測り方の揺れ: 肩まで入る広さで切り出して拡大し、部位分けし直してから測る（faceform.head_view。揺れ ±0.08 → ±0.004）

## 0.6 画像処理の道具（2026-10-10）

`tools/gen/imgproc.py` にまとめる。済の条件: 描いた絵の上で動き、結果を目で見て崩れが無い。記録は `docs/knowledge/imgproc.md`。

- [x] セグメンテーション（セマンティック、インスタンス）、イメージマッティング、背景除去、切り抜きとクリッピングパス、クロマキー、ロトスコーピング（GIF とコマのフォルダ）
- [ ] 動画のロトスコーピング（mp4。ffmpeg が要る）
- [x] インペインティング（範囲を描き直す。`edit.py` にあるものを呼べるようにする）とアウトペインティング（絵の外を描き足す）: `imgproc.py inpaint / outpaint`。丸窓を描き足せ、描き足しの横縞も消えた。描き足しの左の境目にうっすら筋が残る。`docs/knowledge/imgproc.md`
- [x] 超解像（拡大して細部を足す）: `imgproc.py upscale`（Real-ESRGAN のアニメ絵用、`upscale.py`）。832x1216 の騎士を長い辺 2048 に 65.5 秒（CPU）。線がくっきりし、目で見て崩れは無い。顔の白い点を埋める `imgproc.py spotfill` も足した
- [x] 線画の抽出（塗り絵や清書の下地）: `imgproc.py lineart`（XDoG、模型なし、1枚 1秒以内。`library/samples/imgproc-lineart.jpg`）
- [ ] 線画への着色: 白い線画から描き直す（img2img）だけでは塗れない。強さ 0.93 は色が付くが形が変わり、0.72・0.82 は形を守るが色がほとんど乗らない（`library/samples/imgproc-colorize-strength.jpg`）。次の手: 人と同じく、先に閉じた領域へ平らな色を置いてから描き直す（`handdraw.py` の下塗りを使う）
- [x] 色の置き換え・色調補正・色合わせ（`imgproc.py recolor / grade / match`。置き換えは影の明るさを残し、枠で範囲を絞れる。剣士の灰色の襟巻きを赤にできた。`docs/knowledge/lineart.md`）
- [ ] 姿勢推定（骨格の点を取る。ポーズを付けて描くとき、骨格で崩れを数える）
- [ ] 奥行き推定（`layers.py` の Depth Anything を単体で）と、法線から光を当て直すリライティング
- [x] 顔の検出と、顔だけ拡大して描き直す修正（`imgproc.py facefix`。部位分けの顔の枠を 1024 に拡大し strength 0.35 で描き直して楕円の型で戻す。騎士の絵で目の描き込みが増え、継ぎ目は見えない。変わった画素 41,402）
- [x] ノイズ除去、ぼかし除去（`imgproc.py denoise / sharpen`。剣士の JPEG のざらつき 0.81 → 0.39、線が少し柔らかくなる。描き直してぼやけた騎士の輪郭の急さ 51.3 → 93.8。skimage の unsharp_mask はこの環境で壊れた値を返したので scipy で計算する）

## 0.7 デッサン人形（Drawing-mannequin）は道具として参考にする

人形のリポジトリは利用者が手で開発する。こちらから作業を頼んだり、定期実行を回したりしない。
こちらはポーズの決め方（骨格・関節・ポーズ集）を道具として参考にし、使える形になっていれば下絵に取り込むかを判断する。
