# キャラクターデザインのローカルアプリ（計画）

手元の PC で動かし、画面から「狐娘」「サキュバス」のように頼むと、設定資料（多方向の1枚）を描いて検品し、
通ったものを並べて見せるアプリ。Claude に頼まなくても同じことができ、完成したら Claude からも呼べるようにする。

長期開発（long-dev → auto-dev）がこの計画を上から順に進める。終わった項目には [x] を付け、決めたことは
`docs/knowledge/decisions.md` に書く。

## 前提

- 中身は今の道具をそのまま使う。描く・検品するのは `tools/gen/demi.py`、3D の下絵は `tools/engine/viewer/vrm-base.html`
- 公開しない。自分の PC だけで使う（12-1 の「公開せず内側だけで使う」→ Vite + React + TypeScript）
- 描く処理は Python なので、間に Python のサーバー（FastAPI）を置く
- GPU があれば使い、無ければ CPU で動く（CPU では1枚 約3分、初回の読み込み 約10分）
- 置き場所は `app/`（`app/server` が Python、`app/web` が画面）

## 段階

### M1. サーバー（描く仕事を受けて返す）
- [ ] `app/server`: FastAPI。仕事（描く依頼）を受け、順番に1つずつ処理する（同時に2つ描くとメモリが足りない）
- [ ] 仕事の状態（待ち・下絵・描画中・検品・完了・失敗）と、何回目の試行かを返す
- [ ] モデルは1度だけ読み、仕事の間で使い回す（読み込みに約10分かかるため）
- [ ] 種の一覧（`casts/demi3d.json`）の読み書き
- 完了条件: `curl` で依頼を出し、`sheet.png` と検品の結果（`report.json`）が返る。テストで確かめる

### M2. 画面
- [ ] `app/web`: Vite + React + TypeScript + Tailwind
- [ ] 種を選ぶ・新しく足す（部品の形と色、描く言葉、打ち消し）
- [ ] 3D の素体の確認（`vrm-base.html` を埋め込み、部品の付け根を見る）
- [ ] 仕事の進み具合（何分経ったか、何回目か）
- [ ] 結果の一覧: 描いた絵、検品の図（部品ごとの ○×）、落ちた理由。通ったものを `library/samples` に保存する
- 完了条件: 画面だけで、新しい種を足して描き、通った絵を保存まで通せる

### M3. 頼みごとを言葉で受ける
- [ ] 「白い狐の巫女」のような日本語を、種の設定（部品・色・言葉）に変換する
  - Claude の API キーがあれば Claude に変換させる。無ければ、部品と言葉の辞書から組む
- 完了条件: 5種を言葉だけで頼み、設定が正しく作られる（部品の取り違えが無い）

### M4. 一発で起動する
- [ ] `app/start.sh`（Windows は `start.bat`）: 依存の取得、3D の素体の準備（`demi.py setup`）、サーバーと画面の起動
- [ ] README に、初回に何分かかるか、必要なディスク（モデル 約7GB）を書く
- 完了条件: まっさらな環境で、手順どおりに起動して1種を描ける

### M5. Claude からも使えるようにする（アプリが完成してから）
- [ ] MCP サーバー（`app/mcp`）: 種の一覧、描く依頼、進み具合、結果の取得を道具として出す。中身は M1 のサーバーを呼ぶ
- [ ] Claude Desktop と Claude Code への登録手順を README に書く
- 完了条件: Claude に「狐娘を描いて」と頼むと、MCP 経由でアプリが描き、通った絵が返る

## やらないこと（今は）

- 外への公開、ログイン、複数人での利用
- 有料の GPU サービスへの接続（手元の GPU か CPU で動かす）
- 3D の作り込み（3D は下絵に要る部品を足すだけ）
