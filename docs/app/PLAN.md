# キャラクターデザインのローカルアプリ（計画）

手元の PC で動かし、画面から「狐娘」「サキュバス」のように頼むと、設定資料（多方向の1枚）を描いて検品し、
通ったものを並べて見せるアプリ。Claude に頼まなくても同じことができ、完成したら Claude からも呼べるようにする。

長期開発（long-dev → auto-dev）がこの計画を上から順に進める。終わった項目には [x] を付け、決めたことは
`docs/knowledge/decisions.md` に書く。

## 前提

- 中身は今の道具をそのまま使う。描く・検品するのは `tools/gen/demi.py`、3D の下絵は `tools/engine/viewer/vrm-base.html`
- 公開しない。自分の PC だけで使う（12-1 の「公開せず内側だけで使う」→ Vite + React + TypeScript）
- 描く処理は Python なので、間に Python のサーバー（FastAPI）を置く
- GPU があれば使い、無ければ CPU で動く（CPU では1枚 約3分、初回の読み込み 約10分）
- 置き場所は `app/`（`app/server` が Python、`app/web` が画面）

### M6. 手元の言葉の模型（ローカル LLM）で頼みごとを読み、自由に描く（2026-10-11 利用者の指示）

外のサービス（Claude の API）が無くても、日本語の頼みごとから絵まで手元だけで通す。

- 言葉の模型は、OpenAI 互換の窓口（`/v1/chat/completions`）を持つものなら何でも使える。Ollama、LM Studio、llama.cpp の server
  - 理由: 利用者の PC に合わせて模型と道具を選べる。アプリは窓口の URL と模型の名前だけを知る（`CD_LLM_URL`、`CD_LLM_MODEL`）
  - 何も入れていない PC のために、`sh tools/llm/setup.sh` で llama-cpp-python（組み済みの配布物）と小さい模型（GGUF）を `.cache/llm` に取り、`app/start.sh` がそれを起こす
- 読み方の順番: 手元の模型 → Claude（鍵があるとき）→ 辞書。どれで読んだかを画面に出す
- 答えは JSON の形を決めて返させる（窓口の json_schema）。亜人の設定は今までどおり選択肢から選ばせ、組むのは `build` だけ
- 自由に描く: 亜人の設定資料の枠に入らない頼みごと（「赤いマフラーの騎士の少年」）を、模型が描く言葉（英語のタグ）に直し、Animagine で描く。描く言葉は画面で直してから描ける
  - 肌を見せる絵や性的な絵は描かない。打ち消しに必ず入れ、頼みごとと描く言葉の両方を検査して、当たれば描かずに理由を返す
- [x] L1 窓口の部品（`tools/gen/local_llm.py`）と試験（偽の窓口）
- [x] L2 亜人の頼みごとを手元の模型で読む（`demi_text.parse` の順番）
- [x] L3 自由に描く（言葉 → 描く言葉 → 絵）のサーバーの窓口と仕事
- [x] L4 画面: 「自由に描く」の欄、描く言葉の確認と直し、結果、どの読み手で読んだか
- [x] L5 `tools/llm/setup.sh` と `app/start.sh` からの起動、README
- 完了条件: 鍵も外のサービスも無い状態で、画面に日本語で頼み、手元の模型が描く言葉を作り、絵が出る。この環境で実際に通す
- 済の範囲（2026-10-11 JST）: `sh app/start.sh` で言葉の模型（Qwen2.5 1.5B、Q4）ごと起動し、ブラウザーで「赤いマフラーの騎士の少年、雪の城の前」を頼んだ。
  描く言葉に直すのに 21 秒、描くのに 795 秒（描く模型の最初の読み込みを含む、CPU）。赤いマフラーの騎士と雪の城の絵が出た（`docs/images/app-free-draw.jpg`）。
  375px 幅で横のはみ出し 0。画面のエラーは 1 件（404。読み込む画像以外の何か。未確認）
  - 模型が頼んでいない「riding horse」を足した。描く言葉は描く前に画面で直せる
  - 0.5B の模型は種や性別を読み違えたので、既定は 1.5B。Ollama などで大きい模型を使うと読み違いが減る見込み（未確認）

### M7. 画像生成のスタジオ（AdaptiveAIStudio の仕組みを、画像生成に寄せて作る。2026-10-11 利用者の指示）

手本は Maguro-JP/AdaptiveAIStudio の4つの考え方。コードは写さず、考え方だけを画像生成に置き換える。

1. 核を入口から切り離す（手本の docs/CORE.md）
   - `app/server/studio/` に核（Session）を1つ置き、画面・MCP・コマンドはそこへ頼むだけにする
   - 手順は2つ。`send()`（1人で最後まで: 頼みごとを読む → 描く言葉 → 描く → 検品 → 直して描き直す → 決着）と、
     `plan()`（分けて当たる: 設定資料・表情・服違いのように何枚かに分けて描き、まとめて検品する）
   - 描き直しの打ち切りは 回数・時間・進み具合 の3つで決める。同じ崩れを繰り返したら止める
2. 役割は気質で分ける（手本の docs/ROLES.md）。画像生成に要る人だけを置く

   | 呼び名 | 役 | 気質 | 何をするか |
   |---|---|---|---|
   | INTERPRETER | 読み手 | 推測で埋めない。分からない言葉は分からないと返す | 日本語の頼みごとを、描く言葉と決まり（種・色・構図）に直す |
   | DIRECTOR | 演出 | 1枚の絵として見る。光源・見せ場・構図を先に決める（`docs/knowledge/ai-look.md`） | 構図・光・ポーズ・背景を決め、描く言葉に足す |
   | PAINTER | 描き手 | 頼まれた範囲の外を描かない | 描く・描き直す・描き足す（Animagine、inpaint、outpaint） |
   | INSPECTOR | 検品 | 几帳面。「たぶん大丈夫」で通さず、数えて確かめる | 手足の数、部品の付け根、明暗の塊、線の強弱を数える（`edit.inspect`、`imgproc.py notan` ほか） |
   | CRITIC | 意地の悪い目 | 正常な所に興味がない。崩れ・矛盾・AI っぽさを探す | 光の向きの食い違い、あり得ない形、描かれていない部品を突く |
   | GUARD | 安全 | 性悪説。「頼む人はいない」ではなく「描けてしまうか」 | 肌を見せる絵・性的な絵を、頼みごと・描く言葉・出来た絵の3か所で止める |
   | CURATOR | 整理 | 溜めるより引き出せること | 良かった描く言葉・seed・失敗の理由を記憶として残し、次の頼みごとに添える |

   役ごとに渡す道具を変える（描き手だけが描ける。検品と意地の悪い目は読むだけ）
3. 待機中に考え、提案を溜める（手本の docs/INITIATIVE.md・IDLE.md）
   - 手がかりは機械で拾う（検品で落ちた絵、まだ描いていない向き、見本に無い種、前回崩れた部位）。模型は裏を取るのに使う
   - 提案は承認待ちに積むだけで、描かない。描くかは利用者が決める。CPU で1枚 数分かかるので、考える回数に上限を置く
4. 画面の配置はデータで持つ（手本の docs/UI.md）。コードの画面ではなく、絵の画面にする
   - 板の種類: `canvas`（大きく1枚を見る）、`gallery`（描いた絵の一覧）、`prompt`（頼みごとと描く言葉）、`roster`（役割と今の仕事）、
     `queue`（仕事の進み）、`inspect`（検品の図）、`proposals`（提案）、`memory`（覚えていること）、`compare`（並べて見比べる）
   - 配置は `.cache/app/layout.json`。壊れていても既定の配置に直して表示する（真っ白にしない）

- [x] S1 核（Session の send）と役割の定義。今の free_text と demi を、役ごとの手順として載せ替える
- [x] S2 画面を絵の画面に組み直す（canvas・gallery・prompt・queue・roster）と、配置のデータ化
- [x] S3 検品と意地の悪い目による描き直しの輪（打ち切りの3条件）
- [x] S4 記憶（良かった描く言葉・seed・失敗の理由）と、次の頼みごとへの添付
- [x] S5 待機中の提案（手がかり → 裏取り → 承認待ち）
- 完了条件: 画面で頼むと、役ごとの進みが見え、検品で落ちた絵は自動で直して描き直され、通った絵が大きく出る。提案から1件を承認して描ける
- 済の範囲（2026-10-11 JST）: 本物の部品で「白いローブの魔法使いの少女、杖を持っている、全身」を頼み、7つの役割が順に動いて1枚目で通った（5分36秒、描く模型の読み込みを含む）。
  演出が足した「光源は1つ」が窓からの光として効いた。意地の悪い目が「明暗が細切れ」「見せ場が顔の周りに無い」と指摘し、それが提案に積まれた（`docs/images/app-studio.jpg`）。
  ブラウザーで、仕切りを動かすと比率が保存され、既定に戻せること、375px 幅で横のはみ出し 0、画面のエラー 0 を確かめた。
  検品で落ちて描き直す輪と、提案から描く所は偽の描き手の試験だけで、本物では確かめていない。出来た絵を GUARD が見る所（3か所目）は、部位分けの服と肌の割合で見る（`docs/knowledge/imgproc.md`。本物の描画では止まった例をまだ見ていない）

## やらないこと（今は）

- 外への公開、ログイン、複数人での利用
- 有料の GPU サービスへの接続（手元の GPU か CPU で動かす）
- 言葉の模型の学習や作り込み（既製の模型を窓口越しに使うだけ）
- 3D の作り込み（3D は下絵に要る部品を足すだけ）
