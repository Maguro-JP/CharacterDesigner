# AI に手を描かせると崩れる理由と、崩れなくする手順

2026-10-17 に手の形を 1 つずつ頼んで描かせた 12 枚（MeinaMix V11 の全身 5 枚・上半身 8 枚、Animagine XL 4.0 の上半身 1 枚）から。
検品担当が通した絵は 0 枚。崩れの内訳と、それぞれの原因・直し方を並べる。

## 何が間違っているか

| 崩れ | 枚数 | 原因 |
|---|---|---|
| 指が溶ける・本数が読めない | 6 | 手に画素が足りない。全身の絵で手は 60〜100 画素、模型が描く下書き（潜在、絵の 1/8）では 8〜12 マスで、指 1 本が 1 マスを切る。指を分けて描ける細かさが無い |
| 頼んだ手の形にならない（指差し・親指を立てる・胸に手） | 5 | 言葉では指の形を決められない。言葉は「何があるか」を伝えるが「どの指が何本、どの向きか」は伝わらない。蜘蛛の脚の本数も、打ち消しの言葉を 3 回足して減らなかった（`ai-drawing-notes.md`） |
| 両手が重なって溶け合う（胸の前、顎に添えた手） | 2 | 重なった手は学習した絵でも境目があいまいで、模型は 2 つの手を 1 つの塊として描く |
| 手や持ち物が 1 つ多い（腕につながらない 3 つ目の手、2 本目の刀） | 2 | 模型は「手らしい形」「刀らしい形」を絵のあちこちに置く。数を数える仕組みが無い |
| 手が服や背景の色に溶ける | 2 | 青一色の色調では肌と服の明るさが近く、輪郭が描かれない |
| 指が絵の端で切れる | 1 | 構図を決めるのは模型で、手が枠に収まる保証が無い |

道具の側の間違いもあった。

- 目で見た判定が当てにならない。上半身の 3 枚を「頼んだ形が描けた」と見たが、拡大した検品では 3 枚とも戻した（ピースの指が 3 本、カップを片手で持つ、指先が溶ける）。縮小した絵では指の本数は見えない。数字で測るか、拡大して数える
- 測る道具（`tools/gen/hands.py`）は手の位置を手で指定する必要があり、毎枚は測れていなかった。肘と手首から枠を出す `--auto` を足した

## どうすれば描けるか（効く順の見込み）

1. 手に画素を与える。上半身で描き、さらに手の周りを切り出して 1024 画素に広げてから描き直す（顔では `detail.py` で同じことをして、左右の目がそろうようになった）。下書きで指 1 本に 1 マス未満しか無いのが一番の原因なので、これが最も効くと見込む
2. 言葉でなく形で指示する。指の形は、関節の位置の下絵（ControlNet の姿勢、手の 21 点を含むもの）で渡す。下絵は手本の写真や 3D の手から道具が作る（Claude は作らない決まり）
3. 構図で崩れを避ける。片手ずつ見せる、手を顔や他の手から離す、肌と服の色を分ける（打ち消しに monochrome を足す）
4. 多く描いて数えて選ぶ。1 つの言葉で数枚描き、`hands.py --auto` と手の数・腕の数・持ち物の数を数え、外れの少ない 1 枚だけを直す段へ回す
5. 模型を選ぶ。同じ上半身で、Animagine XL 4.0 は MeinaMix より手が大きく、指の形も整った（1 枚だけの比べなので、数を足して確かめる）

## どうすれば間違わなくなるか

- 描いた絵は必ず拡大して数える。手の数は腕の数と、持ち物の数は設定と照らす（検品担当の手順に入れる）
- 指の本数・長さは `hands.py --auto` で測り、外れた手は直す段へ回す。読めない手（袖に隠れた手）は崩れと分けて数える
- 同じ崩れで 2 回落ちたら言葉を足さない。この表の原因のどれかを確かめ、手順（画素・形・構図）を変える
- 結果はこの表の枚数に足していく。直し方が効いたかは、通った枚数の前後で比べる

## 試した手順の結果（2026-10-17、検品担当の判定）

| 手順 | 通った数 | 主な崩れ |
|---|---|---|
| MeinaMix、全身 | 0 / 5（検品前に 3 枚は頼んだ形でない） | 指の溶け、頼んだ形にならない |
| MeinaMix、上半身 | 0 / 7 | 指の本数、3 つ目の手、2 本目の刀 |
| Animagine XL 4.0、上半身 | 0 / 1 | 指が端で切れる、顎の手が溶ける |
| 同上＋手の周りを 1024 画素で描き直す（強さ 0.5、言葉に open hand） | 0 / 1 | 閉じた手まで指を扇に開き 6 本以上 |
| 同上（強さ 0.35、open hand を外す） | 2 / 8（ピース、親指を立てる） | 指の溶け 4、指の欠け・余分 2 |
| 同上＋描き直しを 3 通り描き、手らしさの高いものを選ぶ | 0 / 4 | 指が 6 本以上 2、溶け 2 |
| 強さ 0.35、手のひらの模型で枠、描き直しを手の形の範囲だけ戻す | 4 / 6（手を振る、指差し、親指を立てる 2） | 両手の指の重なり 1、指が細長い 1 |
| 手だけ・足だけを画面いっぱいに描く（1024x1024、人物なし） | 手 1 / 6（指差し）、足 0 / 6 | 手は指が 1 本足りない 2・6 本 1・折った指が塊 1、足は形が読めない 2・指が溶ける 3・脚が 2 本 2 |

分かったこと:
- 描き手の模型と、手だけを大きく描き直す段が一番効いた（0 → 2 / 8）。描き直しを四角ごとでなく手の形の範囲だけ戻すと、さらに 4 / 6 に上がった
- 描き直しの強さを上げる・言葉で「開いた手」を足すと、指が増える。強さは 0.35 前後
- 手を探す模型の「手らしさ」で選ぶと、指を扇に開いた手（指が多い）を選ぶ。手らしさは選ぶ物差しにならない
- 手や足だけを画面いっぱいに描いても指の本数は崩れた（手 6 枚中 5 枚）。画素の足りなさだけが原因ではなく、模型が指の数と並びを持っていない。足を大きく寄せると、頼んだ向きにならず形そのものが読めなくなった
- 肘と手首からの見当は、上半身では肘が枠の外に出て使えない。手のひらを探す模型（MediaPipe の hand_detector）は 3 枚とも手を正しく枠に入れた

## 本実装への案（効く見込みの順）

1. 手の形を絵で渡して描き直す（HandRefiner と同じ考え方）。手のひらの模型で手を探し、手の関節 21 点から「正しい形の手」を作り、その奥行きか関節の図を ControlNet に渡して、手の所だけを描き直す。論文では、言葉だけの描き直しより指の崩れが減ったとされる。言葉では指の本数と向きが決まらないことは、ここでの 8 枚でも蜘蛛の脚でも確かめた。手の形の下絵は手本の写真や 3D の手から道具が作る。注意: 奥行きだけでは手のひらか手の甲かを取り違えることがあると後の論文が指摘している。小さな手は直りにくい
   - 出典: [HandRefiner](https://arxiv.org/abs/2311.17957)、[3D の手の形で導く後の論文](https://arxiv.org/abs/2506.12680)
2. 描き直す範囲を四角から手の形の範囲に絞る。いまは四角ごと描き直すので、顎や髪に触れた手が髪と溶けて半ば透けた（try-301）。部位分け（`.parts.png`）か手のひらの模型の点から手の範囲を作り、その外は元のまま残す
3. 構図の決まりを言葉の前に置く。手を顔や他の手に触れさせない、片手ずつ見せる、手は絵の内に収める。両手が顔の前に重なる絵は 4 枚とも溶けた。other hand down は効かず、頼んでいない手が顔の近くに来た
4. 指の本数を数える検品を足す。手の範囲の骨組み（細線化）から指先の数を数え、5 を超える・3 に満たない手を落とす。手らしさでは崩れた手を選んでしまった
5. 検品担当に手だけの 3 倍の切り出しを渡す。検品担当は全体の図や 1.8 倍の図で数えることが多く、本数に迷いが残った
6. 描き手は Animagine XL 4.0 を使う。MeinaMix の上半身は 7 枚中 0 枚だった
