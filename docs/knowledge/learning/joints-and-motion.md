# 関節の動かし方・付いてくる体の動き・可動域

目標:
1. 主な関節（首・胴・肩・肘・手首・股・膝・足首・指）の可動域を、出典つきの数字で持つ（`casts/rom.json`）
2. 人形の姿勢を数字で照らし、可動域を超えた関節を機械で見つけられる（`tools/engine/rom_check.py`）
3. 関節を動かしたときに付いてくる動き（肩甲骨、骨盤と肩の逆の傾き、首と胴の回り方、重さと逆への傾き）を、
   検品担当が絵の判定に使える決まりにする（`docs/knowledge/joints-and-motion.md`、`sakkan.md` の 2、checker の 10）

判定:
1. `rom_check.py --self-test`: 自然な姿勢 4つで外れなし、わざと壊した姿勢 4つ（肘の逆曲がり、膝の前曲がり、首 170 度、手首の甲側 120 度）で全部見つかる
2. 下絵に使っている実際の姿勢（`pose_prop.py`）で外れなし
3. 検品担当が既存の絵を、関節の表（曲がる向き・可動域）と連動の表で判定し、関節ごとに所見を書ける

現在（2026-10-12、周2の後）: 1・2・3 とも通った。ただし 3 は自然な姿勢の絵でしか確かめていない（逆曲がりのある絵で検品担当が見つけられるかは未確認）
諦める条件: 3周続けて判定 3 で、検品担当が関節の所見を書けない（決まりが使えない）

## 周1（2026-10-12）

仮説: 可動域の数字と曲がる向きを骨の座標で測れば、人形の逆曲がりは機械で止められる。連動は数字にしにくいので、検品の決まりにする
やったこと:
- 可動域を WikEM の表を軸に、AAOS 系・PMC・指の資料で幅を控えて `casts/rom.json` に書いた（足首は WikEM が逆の向きに読める値だったので PMC を採った）
- 人形で、肘と膝を骨の X 軸まわりに +60 度回すと自然に曲がる（前腕が前、すねが後ろ）ことを確かめ、符号を決めた
- `rom_check.py`: 蝶番は親から見た子の X 軸まわりの角、球の関節は振れとねじれ。`pose_prop.py` が姿勢を付けた後に数える
- 試験 `tests/test_rom.py`（角度の計算、親ごと回しても変わらない、余裕の扱い）
判定: 1 は 8/8（入れた角度と出た角度も一致: 逆曲がり 40、首 170、手首は掌屈の限界 -70 を 50 超えて -120）。2 は外れなし。試験 4/4
効いた: 骨の座標で測ると、IK の結果でも休みの姿勢との差で角度が取れた
次: 判定 3。検品担当に既存の絵を、関節と連動の表で判定させる

## 周2（2026-10-12）検品担当が絵で使えるか

やったこと: 検品担当に、騎士の三面図3枚と胸から上の1枚を、関節の表と連動の表だけで判定させた
判定: 4枚とも、関節ごと（首・肩・肘・手首・指・股・膝・足首）と連動ごとに、座標つきの所見を書けた。関節の外れは無し。
関節の表とは別に、後ろの図だけ肩幅が頭の約 3.5 倍（正面は約 1.8 倍）と体つきの食い違いを見つけた
足りなかった決まり（検品担当の指摘）を足した: 両足立ちで骨盤と肩が水平なのは正しい、前かがみの重心（腰を引く）、鎧や手袋で隠れた関節の扱い、組の間で比率がそろうか
未確認: 逆曲がりのある絵での判定。わざと崩れた絵を描いて確かめるのが次
次: 下絵の姿勢づくり（pose_prop、turnaround）で、可動域の検査を必ず通す。崩れた絵が出たら、検品担当が関節の表で見つけたかを事例集に記録する
