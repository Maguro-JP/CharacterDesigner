# 言葉の模型の評価（AdaptiveAIStudio から）

AdaptiveAIStudio は同じ模型（Qwen3.5 の 2B・4B・9B、unsloth の Q4_K_M、共通の置き場 `C:\LLM\gguf`）を、ファイルを作る・直す仕事で比べている。
CharacterDesigner の評価（日本語の頼みを絵の言葉に直す、`chatdraw/models.py` の WORDS の score）と仕事の種類が違うので、点はそのまま移さない。ここには、模型を選ぶときと取るときに効く分だけを書く。

## コーディングの比べ（2026-11-01、CPU 4 コア、GPU なし）

使う人と同じ道（配る形を起こし、画面から 2 つの頼みを送り、出来たファイルを動かして判定）で比べた。

| 模型 | 結果 | かかった時間 |
|---|---|---|
| Qwen3.5 2B | 2 回とも落ちた（出力の誤り、20 分で出来ない） | 169 秒、1267 秒 |
| Qwen3.5 4B | 製品側で引数の崩れを受けたあとは通った。CI の Windows を合わせて 5 回中 4 回通過 | 412 秒 |
| Qwen3.5 9B | 通った | 947 秒 |

## CharacterDesigner に効くこと

- 2B が絵の言葉に足りても、手順を組む・道具を呼ぶ仕事には足りない。仕事の種類ごとに点を分けて持つのがよい。いまの score は「絵の言葉に直す」仕事の点として読む
- 4B は、CharacterDesigner では未確認（score 0）のまま。上の結果は別の仕事の結果なので、4B の score を上げる根拠にはしない
- 小さい模型は、決まった形の出力（JSON、道具の引数）を崩す。崩れ方は「空の並びを足す」「値の中に残りの引数を書く」だった。受け口で崩れを受け、エラーには正しい形の例を入れると、同じ失敗を繰り返さなくなった
- llama.cpp の先読み（InputLookupTokenPredictor などの token predictor）は、頼みの文の語や数字を答えに混ぜることがあった。外すと 4B・9B とも通った。CharacterDesigner の `chatdraw/engine.py` は先読みを使っていない（2026-11-01 に確かめた）

## 模型の取り方

AdaptiveAIStudio の取得と同じ決まりを `chatdraw/fetchfile.py` に入れた。

- 黙り込んだら 60 秒で打ち切る（前は打ち切りが無く、相手が繋いだまま何も送らないと止まったままだった）
- 切れた、黙った、配り元の一時的な不調（429、5xx）は、間を 2・4・8 秒と空けて、最大 3 回まで続きから取り直す
- 404 などは取り直さない
- 取れた長さが合わないものは入れ替えず、`.part` を残して次は続きから取る
- 頭の 4 文字が GGUF でないもの（配り元の案内の HTML など）は置かない
