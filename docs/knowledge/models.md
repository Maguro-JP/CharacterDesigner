# 使ったモデルの違い

画像生成と人体の道具を、何に使い、何が得意で何が苦手だったかで比べる。
速さはこの環境（CPU、メモリ 15GB）で測った値。許諾の詳細は `docs/references.md`。

## 得意と苦手

### Animagine XL 3.1
- 得意: 耳・角・尾・翼・肌の色・年齢を言葉どおりに描く。1つのモデルで子どもから老人まで画風がそろう
- 苦手: CPU では遅い。正面と背面を別々に描くので、服の丈や尾の色が食い違うことがある。尾の大きい種（九尾）は画面からはみ出す
- 注意: 正面は「facing viewer, looking at viewer, straight-on」で書く（「from front」は真横を向いた）

### DreamShaper XL Lightning
- 得意: モンスターの体の組み立てが SD1.5 系より崩れにくい。速い
- 苦手: 範囲を決めた描き直しで、新しい形（角、刺青、鱗）を出せない

### SDXL inpainting 0.1
- 得意: 範囲の外を変えずに、服の上下・長袖・長丈を描き替える
- 苦手: 角・エルフ耳・鱗は出なかった。範囲の外にしみが出ることがある（貼り戻しで消す）

### MeinaMix V11（削除済み）
- 得意: 速い。アニメ風の顔
- 苦手: 耳・角・翼・尾・肌を言葉どおりに描けず、背景や服に移した。女性の老人を若く描いた。モンスターが人型や露出の多い娘の姿に寄った

### DreamShaper 8（削除済み）
- 得意: 構図と服を保ったまま、画風だけリアル風に変える

### MakeHuman ＋ Blender
- 得意: 体型・年齢・性別を数字で変えられる。服の組の着せ替え。体の比率が崩れない
- 苦手: 顔が写実で、アニメ調に寄せても限界がある。写実の顔は利用者に「気持ち悪い」と言われた

## 同時に動かせない

SD1.5 系（約 5GB）と SDXL 系（bf16 で約 8GB）を同時に動かすと、15GB のメモリを超えて強制終了された。
SDXL の本体を2つ持つ（全体用と描き直し用）ときも同じ。1つずつ読み、前の本体を捨ててから次を読む。

## 選び方

- 人・亜人の設定資料 → Animagine XL 3.1（`tools/gen/people.py`）
- モンスター → DreamShaper XL Lightning（`tools/gen/design.py --style xl`）
- 服や肌の部分を直す → SDXL inpainting（`tools/gen/edit.py inpaint`）
- 決まったベースから派生を描く → IP-Adapter（`design.py batch` の from）
  - 体のつくりが手本と違う段階（手足の無い幼年期など）は、手本の形が勝つ。DigiMon の tor-2（羽毛の玉、手足なし）を tor-3（二足の竜）から描くと、
    from_scale 0.6 で8枚中8枚が手本と同じ二足、0.3 でもくちばしと羽毛が出るだけで脚と腕は残った（2026-10-05、seed 7〜10）
  - 手本なしで「羽毛の玉」を描くと、形は塊になるが作風が写実の鳥に流れ、胸のコアも出なかった（DigiMon tor-2、seed 11・12）。
    fluffy feathers の言葉が毛並みの質感を呼んだと見ている（推測）
  - 手足の無い塊は、生き物の型・物の型・塊の型（kind: "blob"）のどれでも腕か脚が付いた（tor-2、2026-10-06〜07、seed 13〜20）。
    物の型がいちばん少なく（足の突起2つと横の突起）、塊の型は顔・角の芽・胸のコアが出たが短い腕と脚が付いた
- 体の比率が要るもの（ドット絵の下地など）→ MakeHuman ＋ Blender（`tools/engine/`）
