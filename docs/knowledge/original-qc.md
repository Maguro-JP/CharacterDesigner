# 独自の作画監督をおまかせに入れた前と後

アプリのおまかせ（chatdraw/omakase.py）の検品に、tools/gen で作ってきた数字の作画監督（measure.py と faceform.py、基準は styles/anime-norms.json）を
chatdraw/origqc.py から足した。見つけた外れは全部、直す囲み（顔・髪・人物）を付けて返し、おまかせが囲みの中だけを直して検品し直す。
利用者が付けた ★ は normlearn.py に「通す」として記録し、基準を学び直す。学んだ基準はアプリのデータの置き場（learn/norms.user.json）に置き、次のおまかせの検品から効く。

## 測った絵

- 戻した絵: library/feedback の README で判定が「戻す」の 87 枚
- 通した絵: library/samples の .png 45 枚（作風の手本として残した絵）
- 前: 今までの検品（handcheck の手・足、requestcheck の頼んだ物と人数）。後: 前に数字の作画監督を足したもの
- 部位分けの模型は 1 回だけ読み、CPU で 1 枚ずつ測った

## 結果

| | 戻した 87 枚 | 通した 45 枚 |
|---|---|---|
| 前の検品が崩れを挙げた枚数 | 87（見逃し 0） | 45 |
| 前の検品の崩れの数（1 枚あたり） | 1089（12.5） | 523（11.6） |
| 数字の作画監督が崩れを挙げた枚数 | 85（見逃し 2） | 41 |
| 数字の作画監督の崩れの数（1 枚あたり） | 137（1.57） | 71（1.58） |
| 後（両方）が崩れを挙げた枚数 | 87（見逃し 0） | 45 |

数字ごとの外れの割合（戻した絵 / 通した絵）:

| 数字 | 戻した絵 | 通した絵 |
|---|---|---|
| hair.blown（髪が白く飛ぶ） | 33 枚（38%） | 8 枚（18%） |
| eyes.found（両目が読めない） | 39 枚（45%） | 11 枚（24%） |
| eyes.iris_delta（左右の瞳の色が違う） | 33 枚（38%） | 26 枚（58%） |
| face.rms（正面に戻すと歪む顔） | 23 枚（26%） | 19 枚（42%） |
| light.inverted（影が光より明るい） | 9 枚（10%） | 7 枚（16%） |

## 分かったこと

- 前の検品は、手と足が読めない絵を崩れとするので、この 132 枚では全部の絵に崩れを挙げた。戻した絵の見逃しは前も後も 0 で、枚数では差が出ない
- 数字の作画監督は、崩れの種類（髪の白飛び、目が読めない、瞳の色違い、顔の歪み、影の向き）を足した。前の検品はこれらを 1 つも挙げていなかった
- 髪の白飛びと両目が読めないは、戻した絵の方が 2 倍ほど多く外れた。数字の検品で崩れを分けられている
- 瞳の色違いと顔の歪みは、通した絵の方が多く外れた。全身の手本は顔が小さく、目と口の点が数画素ずれるため。基準を緩めると戻した絵を見逃すので緩めず、利用者の判定（★ と戻す）から normlearn で境を学び直して直す。顔の点の取り方を直すのが次の作業
- 1 枚を測るのに CPU で約 24.5 秒かかる（前の検品は約 1.9 秒）。部位分けを 2 回（全体と顔の拡大）、奥行きの推定、タグの読みが大きい
