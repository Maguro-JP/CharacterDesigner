# 自分の作風の模型（★ の絵から学ぶ LoRA）

利用者が気に入った絵を、自分専用に学ばせた模型のように使えるようにする設計。土台の模型はそのままにし、
★ の絵から小さな差分の重み（LoRA）を学んで、描くときに強さを付けて重ねる。

## 流れ

1. ★ を付ける: 履歴とライブラリーの絵を右クリックして「★ お気に入りにする」。印はデータの置き場の `favorites.json` に絵の道で持つ（`chatdraw/ownstyle.py`）
2. 集める: 「学習用に集める」で、★ の絵をデータの置き場の `datasets/<日時>/` に `0000.png` と `0000.txt`（説明）の組で写す。説明は wd-vit-tagger-v3（`chatdraw/requestcheck.py` と同じ読む模型）のタグを確からしい順に並べたもの。読む模型が無ければ描いたときの言葉（絵の隣の .json の prompt）を使う
3. 学ぶ（まだ作っていない）: 今の土台の模型に合わせて LoRA を学ぶ。下の「学習」
4. 置く: 出来た `.safetensors` を `C:\LLM\lora\` に置く（`LLM_HOME` を替えたときはその下の `lora`）
5. 使う: AI の欄の「模型」で LoRA を選び、強さ（0〜150%、既定 80%）を決める。初めは「LoRA なし」。`Painter` が `load_lora_weights` と `set_adapters` で重ね、同じ LoRA は 2 度読まない。読めなければ外して描くのを続け、理由を `lora_note` に残す
6. 確かめる: 「自分の作風」として勧める前に、検品（作画監督）を通す。下の「評価」

1〜2 と 4〜5 は作ってある。3 と 6 はこれから作る。

## 学習

### 道具の比べ

| | diffusers の `train_text_to_image_lora_sdxl.py` | kohya-ss sd-scripts |
|---|---|---|
| 使用許諾 | Apache-2.0 | Apache-2.0（一部に元の作者の許諾が付く部品がある。取り込む前に LICENSE を確かめる） |
| Windows | Python と PyTorch が動けば動く。accelerate の設定が要る | Windows の手順が公式にあり、利用者が多い |
| 入力 | Hugging Face の datasets の形（画像と説明の列）。フォルダーから読む小さな変換が要る | 画像と同じ名前の `.txt` をそのまま読む（今の書き出しの形） |
| 出来た LoRA | diffusers の形。`load_lora_weights` でそのまま読める | kohya の形。diffusers の `load_lora_weights` が変換して読める |
| 少ない VRAM の工夫 | 8bit Adam、勾配の積み直し（gradient checkpointing） | 同じものに加え、text encoder の出力の写し置きなど選べる物が多い |
| DiT（SD3、FLUX など） | `train_dreambooth_lora_sd3.py`、`train_dreambooth_lora_flux.py` がある | `sd3` と `flux` の枝に学習の部品がある |

先に sd-scripts を外の部品として呼ぶ形にする。書き出しの形をそのまま読め、Windows で使う人が多いため。
アプリに取り込まず、`C:\LLM` の下に別に入れた Python で動かす（アプリの本体を大きくしない）。

### 必要なもの（SDXL、LoRA の rank 16〜32、1024 画素）

- GPU が要る。NVIDIA の 12GB 以上で動く（8bit Adam と gradient checkpointing を使う）。8GB は 768 画素に落とせば動く場合があるが、出来は落ちる
- 時間の目安: 絵 20〜50 枚、1,500〜3,000 歩で、RTX 3060 12GB で 1〜2 時間、RTX 4090 で 20〜40 分
- CPU では学べない。SDXL の 1 歩に数十秒〜数分かかり、数千歩は数日になる。GPU が無い PC では「学ぶ」を出さない
- 絵の数: 15 枚より少ないと覚え込み（同じ構図しか出ない）が起きやすい。集めるときに枚数を見せ、少なければ足すよう案内する

### 借りた GPU で学ぶ（選べるようにするだけ）

手元に GPU が無い利用者は、借りた GPU（Runpod など）で同じ道具を動かせる。ただし絵を外に出すことになるので、
既定にはせず、利用者が自分で選んだときだけにする。そのときも、絵を送る前に送る先と枚数を見せて確かめる。

### DiT の模型

SD3・FLUX など DiT の土台は、LoRA を掛ける場所（注意の層）と道具が違う。SDXL で流れを通してから、
土台の模型の系統（`models.py` の family）ごとに学ぶ道具を選ぶ形にする。違う系統の LoRA は重ねられないので、
LoRA の隣に学んだ土台の名前を残し（`<名前>.json`）、合わない模型では選べないようにする。

## 評価

LoRA を重ねた絵と重ねない絵を、同じ頼みと種で描き、作画監督（`requestcheck`、手・顔・体の検品）を両方に通す。

- 頼んだ物が描かれない件数と、手・足・顔の崩れの件数が、重ねない絵より増えたら勧めない
- ★ の絵と、重ねた絵のタグの重なり（作風が寄ったか）を数で見せる
- 出来たかどうかを決めるのは利用者。通った LoRA を「自分の作風」として選べるようにするだけで、勝手に既定にしない

## 安全

- 学ぶ絵は利用者が自分で描かせた絵（履歴とライブラリーの作品）だけ。資料（他人の絵かもしれない物）は ★ の対象にしない
- 絵も LoRA も手元に置く。どこにも上げない（借りた GPU は上の通り利用者が選んだときだけ）
- 書き出しは写しを取るだけで、元の絵を動かさない・消さない

## ディスク

- 書き出し: 元の絵と同じ大きさ（1 枚 1〜3MB の PNG、50 枚で 50〜150MB）。説明の .txt は数百バイト
- LoRA: rank 16 で約 50MB、rank 32 で約 100MB
- 学習の道具: Python と PyTorch（CUDA）と sd-scripts で 5〜8GB。土台の模型は今の `C:\LLM` の物を使い、写さない

## 失敗したとき

- ★ を付けた絵が消えていた: 飛ばして、見つからない枚数を知らせる
- 読む模型が無い: 描いたときの言葉で説明を書く。それも無ければ空の説明にし、空の枚数を返す（`no_caption`）
- LoRA が読めない（壊れた、系統が違う）: 外して描くのを続け、理由を残す
- 学習が途中で落ちた（VRAM が足りないなど）: 画素数と batch を下げた設定を勧める。途中の重みは使わない
