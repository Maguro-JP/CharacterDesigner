## 2. 現象と確認状況

### 2.1 AI生成・工程制御

- [利用者報告] AIモードで工程1以降が飛ばされる。
- [利用者報告] AIモードの生成品質が落ち、画像が大きく崩れる。
- [コード確認] `chatdraw/phases.py` の精密モードは12工程を順に実行する構造だが、崩れが残っても戻り条件に該当しなければ次工程へ進む経路がある。
- [コード確認] 検品の `readable` が全工程共通の不合格ゲートとして使われていない。最終的な `checked` の値だけで処理全体を未完成にする構造ではない。
- [コード確認] `chatdraw/omakase.py` には構図生成・部位修正・描き直しの構想があるが、精密モードとは異なる制御経路である。
- [コード確認] `AUTO_FINISH = ()` で、自動仕上げは無効になっている。
- [未確認] AIモードで工程が飛ぶ具体的な条件、UIからの実呼び出し経路、各分岐での例外・早期終了の扱い。
- [未確認] 実際のモデルが各工程でどのように呼ばれ、生成品質にどう影響しているか。

### 2.2 モデルの役割分担

- [利用者指摘] 髪と仕上げ加工が同じ役割に入っているのは不自然。
- [コード確認] 精密モードの12工程は同じ `painter` を受け取っており、工程単位のモデル分担は確認できていない。
- [コード確認] AIモードには能力・部位による候補選定がある。
- [未確認] 設定画面の役割選択が保存され、実行時に意図したモデルへ正しく結びつくか。
- [未確認] 髪・顔・身体・衣装・ディテール・仕上げの責務が重複せず機能しているか。

#### 役割分担の再設計案

| 役割 | 責務 | 備考 |
|---|---|---|
| Main / Composition | 構図・全体の初期生成 | 全体の土台を作る |
| Body | 骨格・体型・ポーズ | Face/Hair と位置関係を共有 |
| Face | 顔・目・表情 | 髪の生え際・顔周辺と連携 |
| Hair | 髪型・毛束・髪質 | 独立した描画責務。仕上げ加工とは分離 |
| Clothing | 衣装・装飾 | 体との接続・重なりも検品 |
| Detail | 線・局所ディテール | 部位修正を担当 |
| Finishing | 画質改善・仕上げ加工 | 描画担当と独立 |
| Inspection | 検品・合否判定 | 描画担当とは独立した評価経路 |

これは確定仕様ではなく、既存コード・対応モデル・利用可能な機能を照合して確定する設計案。

### 2.3 仕上げ・「綺麗にする」加工

- [利用者報告] 「綺麗にする」系の加工がほとんど機能していない。
- [利用者報告] 加工後に画像が綺麗になるどころか、汚く・崩れることがある。
- [コード確認] `chatdraw/finishers.py` に加工機能の登録・ready判定がある。
- [コード確認] 登録されていることと、UIから実行されて画像が改善されることは別問題。
- [未確認] 各機能のUI接続、実行条件、対象マスク、画像入出力、実画像での改善率。

各加工について「何を改善するか」「どの領域を変えるか」「変えてはいけない領域」「実行できない条件」「品質を悪化させた場合の扱い」を明文化する。

### 2.4 通常の描画・編集ツール

AI機能とは独立して、通常の描画・編集操作も棚卸しする。対象は少なくとも次のとおり。

- ブラシ、消しゴム、色、スポイト
- 選択、移動、変形、切り抜き
- レイヤー作成・削除・順序・表示・統合
- Undo / Redo
- 拡大縮小、パン、キャンバス操作
- マスク、部分加工、保存、再読込
- ショートカット、右クリックメニュー

UIに表示されている機能を一覧化し、未実装・条件付き・正常動作を区別する。単体操作だけでなく、操作の組合せ、Undo/Redo、保存再読込も検証する。

## 4. 作業順序

1. #429 の設計提案をレビューし、現行コードとの差分と移行順を確定する。
2. P0の #431・#432 を先行し、工程スキップと不合格通過を止める。
3. #433 でモデル役割と実際の呼び出しを一致させる。
4. #434 で仕上げ加工を一つずつ検証・修正する。
5. #435 で通常ツールを機能一覧に沿って修正する。
6. #436 の固定画像による視覚回帰テストを整備し、以後の変更で品質が戻らないようにする。
7. #437 で進捗・完了・失敗を見えるようにする。

依存関係により順番は調整してよいが、P0の合否制御を放置したまま加工機能を増やさない。

## 5. 完了判定の共通ルール

Issueを閉じる前に、以下をすべて記録する。

- [ ] 原因と再現条件を特定した
- [ ] 変更したファイルと変更内容を記録した
- [ ] 回帰テストを追加した
- [ ] 関連テストを実行し、件数と結果を記録した
- [ ] 実画像で変更前後を比較した（画像処理・生成品質に関係する変更）
- [ ] 対象外領域や既存機能を壊していないことを確認した
- [ ] 未解決事項・制限・未検証の環境を記録した
- [ ] PRのCIが通り、レビュー可能な状態になった

**禁止事項**
- テストを実行していないのに「テスト済み」と書かない。
- 実画像を見ていないのに「画質改善を確認」と書かない。
- 処理が最後まで走っただけで「完成」と判定しない。
- 失敗や未対応をログから消して成功扱いにしない。
- 効果が確認できない修正を、変更行数だけを根拠に完了にしない。

## 6. 進捗更新のルール

- 進捗の正本は [統合Issue #438](https://github.com/Maguro-JP/CharacterDesigner/issues/438) とこの文書にする。
- 作業開始時にIssueへ着手コメントを残す。
- 実装中は、判明した原因・変更ファイル・テスト状況をIssueへ追記する。
- 作業を中断する場合は、最後に確認できた状態・未完了作業・次の一手を記録する。
- 完了時は証拠（テスト結果、画像比較、PR）を添えてチェックを付ける。
- 進捗が無いのに「作業中」と表示し続けない。実際の状態に合わせて更新する。

## 7. 現時点の検証状況

- GitHub上のリポジトリ構成、関連コード、既存Issue・PRを静的に確認した。
- この計画を作成した時点では、pytest / unittest、GitHub Actions、GPU実機、実画像での動作確認は実施していない。
- したがって、本計画に記載した不具合のうち「利用者報告」「未確認」としたものは、今後の再現・検証対象であり、すべてを再現済みと主張するものではない。
