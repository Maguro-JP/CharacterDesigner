# 技術

## 描画器 tools/build.py（2026-09-29）

- 流れ: 部品を SS=8 倍で塗る → 部品ごとに光を当てる → 奥から重ねる → 落ち影 → 8x8 の塊ごとに1ドットへ →
  素材の色段に減色 → 輪郭を外に足す → 孤立ドットの掃除 → touchups
- 厚み: マスクを部品の太さ×0.35 でぼかした膨らみを高さとみなし、勾配から法線を取る。
  膨らみの高さを太さに比例させないと、太い胴がほぼ平ら（法線がほぼ正面）になり明暗が出ない
- 輪郭は外側に足す。内側の外周を塗り替えると、2ドット幅の剣が輪郭だけになり中身が消えた
- 頭の高さと体の枠は描き上がりから数える（`head: true`、`prop: true`）。輪郭のドットは接する部品すべてのものとして数える
- 依存は Pillow だけ。28x39、部品22個で 0.5 秒前後
- Pillow 12 で `getdata` が非推奨。`get_flattened_data` があればそちらを使う（`_data`）
- `strands`: 部品の明るさに sin の縞を足す。`angle` は縞が変わる向き（度）、`period` はドット単位の周期、`amp` は振れ幅。
  部品の明るさが段の境から遠いと縞が段を越えないので、振れ幅はその部品の明るさの位置で決める
- 色数が上限に当たったら、素材どうしで段を共有する（金の暗い段 = 革の明るい段）。使用数の少ない色から探す
- `base` と差し替え（`remove` `override` `add` `materials`）: 職業ごとに頭や体格を書き直さないため。`load_spec` が読む。
  `add` の部品は `after` か `before` で重ね順を決める
- `pixline`: 仕上がりの格子で Bresenham の線を引き、そのドットを丸ごと塗る。細い斜めの剣や槍に使う。
  傾きは 1:5 前後が段がそろってきれい。1:3 だと段が不ぞろいに見えた
- 継承は2段以上でもよい（神官 → 剣士 → 戦士）。ただし `touchups` は顔の形ごとに違うので、顔を変えたら差し替える
- 長い髪は `head: false` にする。頭身の頭は前髪の上端から顎まで
- `tools/fmt.py`: parts.json を幅 110 で整える。indent=1 の json.dumps だと座標まで1要素1行になり、3人で 1984 行あった。整えて 479 行
- 弧（弓）は `cut` で作る。外の楕円から、中心を横にずらした楕円をくり抜く
- `add` は書いた順に足すので、`before` と `after` に書けるのは元にある部品か、それより前に足した部品だけ
- `touchups` の色に `null` を書くと透明にする。輪郭から突き出した鼻を消すのに使った
- `touchups` も継承される。親の顔を変えると子の顔も変わるので、顔を固定したい子は `touchups` を自分で持つ（狩人で起きた）
- 動きのコマ: parts.json の `frames`（例 `{"name": "idle-2", "dy": 1}`）と部品の `breathe`。書き出しは `sprite.<名前>.json`。
  touchups は既定で頭と一緒に動く（`breathe: 0` で止める）。並べ図と GIF は `tools/anim.py`
- 歩き: `frames` の `move`（部品ごとの `offset` と `points` のずらし）と `body_dy`（move に無い部品の上下動）。
  move に書いた部品は body_dy で動かないので、上下動させたい腕は offset に自分で足す。持ち物（剣、弓）は手と同じ量を書く。
  `frames` は継承で丸ごと置き換わるので、子で歩きを書くときは `idle-2` も書き直す
- `tools/anim.py --anim walk` で `sprite.walk-*.json` だけを並べる
- `mirror_frames: true` で右向きのコマを自動で作る。`reduce_colors` は styles の `max_colors` を超えたコマだけ、最少の色を最も近い色へ寄せる
- コマの `override`: そのコマだけ部品を差し替える。構えが変わる動き（歩くときの持ち方）に使う。適用は反転と move の前
- 筒（capsule）の直線上に点を足しても、縮小後に1ドット変わることがある（点ごとの円の塗りと多角形の塗りの端の差）
- `line_same`: 同じ素材の部品どうしでも境目の線を引く（手前の部品に書く）。素肌の腕と胴に使った
- `transforms`: 部品の拡大縮小。上から順にかける。右向きでは origin も折り返す。`frame: "child"` を書くと check.py は styles の `canvas.frames.child` の範囲で数える
- `intended`: sprite.json に、仕上げで置いた1ドットの座標を書く。check.py は孤立ドットの数から除く
- 作風の追加は styles/<id>.json の `render` を書くだけで、全職業に効く。頭の大きさは `parts: "head"` の transforms で決める
- 速さ（2026-09-29）: 部品の陰影と重ねを部品の範囲（getbbox）だけで走らせ、法線の正規化をその場で計算した。
  試験 28.4 → 16.3 秒、9人 × 3作風の書き出し 35.9 → 18.0 秒。書き出しは1ドットも変わらない（再現性の試験で確認）

## 顔の足し算と引き算（身長 32〜40 ドットの立ち絵）

実機の立ち絵を拡大して数えた（画像はリポジトリに置かない）。

- 引く: 鼻、口、眉、奥の目。この大きさで置くと、顔の部品が多すぎて人の顔に見えなくなる
- 残す: 目の組み方（左向きの 3/4。この作風は斜め上から見下ろす視点）
  - 真横の横顔なら両目の行を揃える。斜め上から見下ろす視点では、奥の目を手前の目より1段上に置く
  - 目は黒目を黒にしない。瞳の色（暗い色）だけで置く。黒は眉と輪郭に使う
  - 手前の目: 眉2ドット（黒目と白目の真上）、その下に瞳の色1ドット、後ろ側（頭の側）に白目1マス
  - 奥の目: 瞳の色1ドットだけ。白目も眉も描かない。手前の黒目との横の間は肌2ドット
  - 白目を黒目の前に置くと横目になる（横目の人物として描く場合だけ前）
  - 肌の段は、黒の輪郭の内側に最も暗い茶、暗い茶、中間、明るい黄土。桃色に寄せない
  - 肌は明暗の幅を広げない（素材の contrast 1.0）。目が乗る面が影に沈むため
- 見下ろす視点は体にも出る: 胴は斜め前を向いて胸と両肩が見える。帯は中央が下がる弧。足を開いた構えで拳と足が大きい
- 全身の縦の割合（手本の戦士、31行）: 頭11・胴8・腰7・脚5。脚が短い。大人の頭身 2.5〜2.9
- 服の情報量は揺らぎではなく描き込みで出す。手本の服は1ドットおきの縦縞（布のひだ）で、隣と色が変わる割合が高い。素材の `folds`（周期2、強さ 0.3）で出す。0.12 では影の中で段をまたげない。頭巾のように頭を包む布には付けない（髪に見える）
- 髪の地は暗く、明るい房は1ドットの点として散らす。髪の素材は揺らぎ 0.45、段の境 0.55/0.86（大半が暗い段、揺らぎの山だけが明るい段）。頭頂に明るい面を1枚作らない
- 銀や白の髪は、金属と同じ青灰の段にすると兜に見える。暗い紫がかった灰から黄みのある明るい色へ振る（手本の盗賊）
- 足す: 髪。頭の半分以上を髪にし、前髪を目のすぐ上まで下ろす。縁はギザギザにし、明るい房の筋を入れる
- 顔の立体は輪郭の形でなく明暗で出す（光の側が明るく、奥の頬と顎が暗い）
- 顔の向きは、目の位置（顔の前寄り）と、明暗の分かれ目で伝える。輪郭で鼻を突き出すと壁画になる

## 色の段・影・質感（実機の立ち絵の実測）

実機の立ち絵4人・941体の平均。画像はリポジトリに置かない。

- 1体 28〜40 色。素材ごとに5〜7段。最も多い色はほぼ黒（#181818、全体の26%）で、輪郭と影の奥を兼ねる
- 暗いドット（明るさ 70 未満）が全体の半分前後。光の側より影の側の面積が広い
- 孤立ドットが約2割。面の質感はここで出ている。掃除で消すと、のっぺりする
- 隣と色が変わる割合 0.80〜0.87。平らな面はほとんど無い
- 描き方への落とし方: `texture`（deep、expand、contrast、pivot、amp、keep_orphans_within）。平らな塗りの作風には持ち越さない

- 輪郭と境の線は、どの素材でもほぼ黒（明るさ 30 以下）にする。明るい素材（鎧、白い服、金具）の輪郭を明るくすると、全身がぼやける。手本は全身の 26〜40% がほぼ黒
- 服や鎧の鮮やかさは抑える（手本の平均 0.19〜0.39）。肌だけは鮮やかなまま（手本 #d8a860、彩度 0.56）。`texture.saturation` と素材の `keep_saturation`

## 髪の輪郭（2026-10-01）

- 手本の髪の外周は滑らかな弧にならない。1〜2ドットの房の先が輪郭から飛び出し、ギザギザになる
- 形の段階で、外周の点の間に外へ 0.2 H 出る房の先を挟むと、縮小後も段として残る。0.1 H では輪郭付けで均されて丸いままだった
- 頭頂より前には付けない。頭が1行高くなり、頭身が範囲から外れた（`tools/body.py` の `head_parts`）

## 画面の下端（2026-10-01）

- 輪郭は形の外側に付ける。靴が画面の最下行を越えると底の輪郭が切れ、足が輪郭の無い平らな帯に見える
- 体の高さも短く数えられるので、頭身の検査が切れたまま通っていた。最下行に明るい色が無いことを試験で見る（`tests/test_build.py`）
- 仕上げのドット（touchups）は shift 込みの画面の座標。shift を変えたら touchups も同じだけ動かす

## 足の開き（2026-10-01）

- 手本の立ち姿は脚を少し開き、左右の靴の間に背景が2ドット見える。靴は1足ずつ輪郭で囲まれる
- 輪郭は外側に1ドットずつ付くので、形の段階で靴と靴の間を 3.6 ドット以上あける。0.6 ドットでは輪郭同士がつながり、1本の帯になった

## 腕と胴の境目（2026-10-03）

- 手本の腕は、胴と明るさがはっきり違う（袖と胴着で素材が違うか、光の当たる側の腕が明るい）
- こちらは8職業すべてで手前の腕と胴が同じ素材で、境の線が引かれず腕が胴に溶けていた
- 境の線（`line_same`）だけでは足りない。線の色が胴の影の色とほぼ同じで見分けが付かなかった（変わったドットは0〜8）。手前の腕を明るい側に寄せる（`bias` 0.2）と、腕が明るい帯として胴から分かれる

## 情報量の内訳と輪郭の色（2026-10-03）

- 隣と色が変わる割合を縦でも数えると、手本 0.73〜0.91 に対してこちら 0.54〜0.68 で、横より差が大きい
- 揺らぎ（amp）を3倍、孤立ドットの掃除を緩める、色数の上限を外す、のどれでも縦は 0.60→0.61 程度しか動かなかった。原因はそこではない
- 縁と内側に分けると、縁（外周に接するドット）で差が大きい（手本 0.67〜0.80、こちら 0.42〜0.58）。手本の輪郭は1色ではなく、内側の明暗に合わせて暗い範囲（明るさ 24〜74）で色が変わる
- `texture.outline_tint` で、外の輪郭を内側の暗い2段へ寄せる。0.3 で横の平均 0.73→0.76、縦 0.60→0.62。明るい段まで寄せるとシルエットが緩み、明るい縁の検査が落ちた

## ひだをうねらせる案は採らない（2026-10-03）

- 縦の変化を増やすために、ひだの縞を流れに沿ってうねらせた（振れ幅 0.5〜1.2 ドット、周期 3〜5）
- 縦は 0.63→0.66 に上がるが、横が 0.76→0.70 に下がり、合計は変わらなかった。見た目は布が格子柄や斑に見えて悪くなった
- 手本の胴着の縞はむしろ真っすぐ。縦の変化は、縁飾り・帯・裾の横の線で作っている
- 布の上から下へ明るさを落とす案（drop 0.15〜0.3）も試したが、横 0.76→0.68、縦 0.63→0.61 と両方下がった。暗い面が広がり、段が同じ色にまとまる
- 残る候補は横の要素（縁飾り、帯、裾の折り返し）を職業ごとに足すこと。形の仕事なので、素材の設定では届かない

## 裾の縁取り（2026-10-03）

- 手本の上着は裾に金の縁取りがあり、真っすぐな縦縞を横切って縦の変化を作る
- 部品に `band_of: {part, width}` を付けると、指定した部品の下端の帯を形にする。元の部品の形から作るので、職業ごとの裾の形や歩きの揺れに付いていく。元の部品が無ければ描かない
- 金の帯は影の側で茶色に沈む。`bias` 0.3 で金に見える。縞（strands）を 0.5 まで強めると端が暗い茶に落ちた
- 裾が太腿の途中で終わる上着（剣士）では、縁取りが脚の間の金の塊になり、帯の留め具に見えた。長い上着（学者）だけに付けた

## 顔の肌の段の割合（2026-10-03）

- 手本の顔の肌は 明るい #d8a860 が 51%、中間 #9c6838 が 31%、暗い #583018 が 18%
- こちらは段の境 [0.3, 0.55] で、戦士の顔は明るい 78%・暗い 22%、中間は 0% だった。顔が1色の面に見え、平らだった
- 境を [0.38, 0.7] に上げると、戦士 42/38/20、剣士 49/23/29、踊り子 55/33/12 になる。顔の奥側と顎の下に中間の色が入る

## 髪の光の段（2026-10-03）

- 手本の黒っぽい髪は、明るさ 135〜180 の毛筋が約1割ある（明るさの分布 60/21/10/10%）。こちらは髪の3段の最も明るい色でも 106〜128 で、135 を超えるドットが無く、髪が1つの塊に見えた
- 素材の `shine: {mix, step}` で、最も明るい段の上に白寄りの光の段を足す。mix 0.45・step 0.9 で、135〜180 のドットが 10〜14%
- 職業ごとに髪の素材を丸ごと上書きしているので、戦士に足しても他の職業には届かない。髪の素材を持つ全職業に同じ設定を書いた
- 盗賊の瞳が赤茶なのは、職業ごとに指定した瞳の色（#6a2a24）で、減色の不具合ではなかった（2026-10-03 の日報の記述を訂正）

## 3D の土台（2026-10-03）

- この環境では `pip` で Blender の Python 部品（bpy 4.2、519MB）が入る。Eevee は GPU 用の libEGL が無く落ちる。Cycles の CPU 描画は 256 ドット四方で約1〜5秒
- MPFB（MakeHuman の Blender 用部品）は `bpy.ops.extensions.package_install_files` で画面なしでも入る。基本素材（281MB、CC0）は `bpy.ops.mpfb.load_pack` で読む。髪10種、現代の服、体型の差分、骨が使える
- 頭身の縮め方: 骨で脚を縮めると足が浮いて腰が沈んだ。頂点を高さで区切って、首の付け根から上を 2.2 倍、股から下を縦に 0.55 倍にすると約 2.9 頭身になる。形の鍵（体型の差分）の全段に同じ変形をかけ、髪はそのあとに被せると頭に沿う
- 残る課題: 服の合わせ用の補助の形が肩と脚に残る、腕が A の字に開いている、素材ごとの塗り分けと、今の縮小・減色・輪郭の仕組みへのつなぎ

## 3D からドットへ（2026-10-03）

- Blender では2枚を描く。部位ごとに決まった色で塗った絵（放射の素材、縁のぼかし無し、標本1）と、全部位を白い拡散の素材にして左上から光を当てた絵
- ドット化は今の描画器の後半（`build.finish`: 縮小・減色・輪郭・掃除・色数の上限）をそのまま通す（`tools/engine/topixel.py`）。素材の色段は既存の職業の parts.json から借りる
- Blender の光は中央 0.83、上が 1.0 に張り付き、ほとんどが最も明るい段に入った。部品から描くときの分布（下位10% 0.30・中央 0.65・上位10% 0.95）に3点で合わせる
- 腕は上腕の骨（upperarm01.L/R）を Y 軸で左右逆向きに 60 度回すと体の脇に下りる（X、Z 軸は腕が前後に回った）
- bpy は描き終えた後の後片付けで落ちる（Segmentation fault）。書き出しの後に `os._exit(0)` で抜ける

## 画像生成のベース（2026-10-03）

- この環境（CPU 4 コア、メモリ 15GB、GPU 無し）で、CPU 版 torch と diffusers が入る。Hugging Face からモデルを取れる
- MeinaMix V11（アニメ風、SD1.5 系）＋ LCM-LoRA で 6 段、512x768 が 1 枚 約 56 秒（1段 約 7 秒）。モデルの読み込みは約 17 秒
- img2img でリアル風（DreamShaper 8、strength 0.55）に描き直すと、構図・人物・服を保ったまま画風だけが変わる（約 41 秒）
- 絵からドット絵: 四隅からの塗りつぶしで背景を抜き、いちばん大きい塊（本人）だけ残し、箱で縮小して減色、外側に暗い輪郭。約 1 秒
- 「設定資料（design sheet）」と書くと小さな別の姿が写り込む。決まり文句から外し、否定に multiple views を入れた
- ドット絵にすると、元の絵が約 7 頭身なので顔が潰れる。箱庭ドットの頭身（約 2.7）へは、頭を大きくする変換が要る

## 画像生成の絵を箱庭ドットに寄せる（2026-10-03）

- SD1.5 系＋LCM（guidance 1.5）は指示の効きが弱く、「chibi, super deformed, 3 heads tall」でも約 7 頭身で描いた
- 絵の変形で頭身を下げられる: 人物の上 15.5% を頭として 1.7 倍、首から下を縦に (頭身-1)×頭の高さ÷体の高さ 倍。7 頭身の絵が約 2.8 頭身になる
- そのまま縮めると、顔は肌色の塊になり目が消える。全体が暗くくすむ。箱庭ドットに届かせるには、目の仕上げと、色・明るさの合わせ込みが要る
- 16ビット機風（24 ドット）と 16x16 は、縮めるだけでは人の形として読めない。小さい作風ほど、形を描き直す工程（輪郭の整理、色の置き直し）が要る

## 指示文は 77 トークンで切れる（2026-10-03）

- SD1.5 の文章の読み手（CLIP）は 77 トークンまでしか読まない。決まり文句（PREFIX）＋人物＋作品の共通の世界観を足すと超え、後ろの「角灯」「白い背景」が絵から落ちた（迷宮定石の探索者で4枚とも）
- `encode()` で 75 トークンずつに分けて読み、横につなげて渡す。同じ指示で白い外套と角灯が出るようになった
- 先頭の言葉ほど強く効く。共通の「暗い青黒の配色」を頭に置いたら白い外套が黒くなった。人物の指示文を先に、共通を後ろに置く。迷宮の画面の配色は人物には書かない

## 画像生成は1つずつ流す（2026-10-03）

- SD1.5 系（約 5GB）と SDXL 系（bf16 で約 8GB）を同時に動かすと、15GB のメモリを超えて先に動いていた方が強制終了された（カーネルの oom-kill、深層ギルドの人の分が1枚で止まった）。終了の印が出ないので、絵の枚数で確かめる
- モンスターは SDXL 系（`--style xl`、DreamShaper XL Lightning）で描く。亀で比べ、SD1.5 系より体の組み立てが崩れにくかった。それでも手足の数の破綻は出るので、`docs/knowledge/monster-design.md` の検品表で1枚ずつ見て `rejected` に書く
- SDXL 系も 77 トークンで切れる。DigiMon の作風を共通に足したら 41 枚すべてで後ろ（2D の塗り、白い背景）が切れ、背景の入った絵になった。`encode_xl()` で2つの読み手それぞれ 75 トークンずつ分けて読む（88 トークンのゴロンで白い背景と作風が効いた）。共通の文を変えたら長さに頼らず、この処理で全部読ませる

## SDXL 系の絵をドット絵に落とす（2026-10-03、DigiMon のベース5体）

- `design.py pixel --preset monster64`（高さ 64、24 色、区画の最頻色で縮める）。高さ 96 は `--height 96`
- 背景: SDXL 系は灰色のグラデーションと床の影を描くので、四隅の色との比較では抜けない。となりの画素との差（step 4）で塗り広げる
- 縮め方: 平均で縮めると境目の中間色が粒になる（孤立ドット率 0.067）。大きいまま減色して区画の最頻色を取ると 0.013
- 作風を指定しない pixel の既定が箱庭ドット（2.8 頭身への変形）になっていて、角や耳が横に寝た。指定しなければ変形しない
- 白い体（ハク）は背景との差が小さく、顔の陰影が減色でつぶれる。高さ 64 では目鼻が読みにくい（未解決）

## 人の性別と年齢の描き分け（2026-10-03、同じ騎士で性別3×年齢4を描いて確かめた）

- 男女: `gender` で描き分けられた。男性は「1boy」だけでは中性的な美形に寄るので、肩幅・顎・首・短い髪を書く
- 中性的: `gender: "androgynous"` で、男女どちらとも読める顔と体になった
- 子ども: 「約7歳、頭が大きく脚が短い、ふっくらした頬」で幼く見えた（「約10歳、4頭身」だけでは十代と同じ頭身だった）
- 中年・老人: アニメの人物向けのモデル（SD1.5 系）は、言葉を強めても女性の老人を若い顔で描いた。`age` が middle / elder の人は自動で SDXL 系で描く。
  年齢の形容は性別の名詞に直接付ける（「elderly woman knight」）。離して書くと若い顔に戻った
- 裏の生成を止めるとき `pkill -f <パターン>` を使うと、そのパターンを含む自分のシェルまで止まった（3回）。`ps -eo pid,args` で番号を見てから kill する
- 止める条件の文字列が、同じコマンドの中の「流し直す命令」にも合ってシェルごと止まった（4回目）。止めるコマンドと流し直すコマンドは分け、`ps -eo pid,comm,args | awk '$2=="python3" && /design.py batch/'` で python の処理だけを選ぶ
