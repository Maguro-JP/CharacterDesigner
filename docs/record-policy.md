# 記録の基準

このリポジトリに残す文書（Markdown、テキスト、設定の説明、コードのコメント、コミットと PR の文）に何を書き、何を書かないかの基準。
`tests/test_record_policy.py` が、機械で見分けられる分を毎回検査する。

## 判断の軸

- このリポジトリが明日公開されて、知らない人が読んでも困らず、役に立つか。
- git に入れたものは、消しても履歴に残る。迷ったら書かない。後から足すのは簡単だが、消すのは難しい。
- 書くのは、次に読む人（人でも AI でも）の判断を変えるものだけ。

## 書くもの

| 種類 | 中身 | 置き場所 |
|---|---|---|
| 再現に要る事実 | 題材、模型、プロンプト、種、設定値、選んだ絵と選んだ理由（1行） | 絵の隣の `.txt`、`library/` |
| 決めたこと | 何をどうするか、理由、選ばなかった案、触る場所 | `docs/knowledge/decisions.md` |
| 分かったこと | 「AI に描かせるとこうなった」「この処理で良くなった」 | `docs/knowledge/ai-drawing-notes.md` ほか `docs/knowledge/` |
| 結果の数字 | 何件、何画素、何秒、何バイト | PR の説明、`docs/progress/` |
| 失敗と次からの手順 | 場面・起きたこと・判定の誤り・次から | `.claude/skills/lessons/LESSONS.md` |
| 出典 | 参考にした作品名、記事、ページ | `docs/references.md` |

## 書かないもの

| 種類 | 理由 | 代わりに書くこと |
|---|---|---|
| 利用者の言葉の引用、利用者の反応（評価、叱責、感情） | 会話の記録であって、設計の記録ではない。公開されると第三者の発言が晒される | 何が起きたか、何を決めたか |
| 謝罪、言い訳、自分の評価 | 次に読む人の判断を変えない | 次からの手順 |
| 落とした絵がどう見えたかの描写 | 読む人の役に立たず、表現によっては公開できない | 落とした枚数 |
| 検品で何を落とすかの細目 | その場で判断するもの。文書に並べると、それ自体が公開できない文になる | 書かない |
| 作業中の推測、試行錯誤の経緯 | 結論と混ざって誤解を生む | 結論だけ。経緯を残すなら git に入らない `.worklog/` |
| 秘密情報（鍵、トークン、接続文字列）、個人情報（氏名、メール、アカウント） | 漏れると取り返せない | 環境変数の名前、参照のしかた |
| 文章を書いた AI のモデル名 | 署名は内容と関係しない | 書かない。絵の生成に使った模型の名前は再現に要るので書く |
| README と PR の説明の中の参考作品名 | 作品名は出典の場所にまとめる | `docs/references.md` |

## 書き方

- 事実と結論から書く。何をしたかより、なぜそうしたか（何を避けたかったか）。
- 主語は物と処理にする（「模型は水着を描かなかった」）。人の反応を主語にしない（「〜と言われた」と書かない）。
- 失敗の記録も同じ。起きたことは事実だけ、判定の誤りは自分の判断の筋道だけを書く。

## 検査

- `tests/test_record_policy.py` が、git に入っている文書から、利用者の発言の引用や反応を表す言い回し、AI のモデル名の署名、鍵の形の文字列を探す。
  見つかったら試験が落ちる。止まる前のフック（`.claude/hooks/test.sh`）で毎回流れる。
- 機械で見分けられるのは言い回しだけ。言い換えた文や、落とした絵の描写は、書く人が上の表で判断する。
- 言い回しの一覧は試験の中にある。新しい書き方を見つけたら、一覧に足して二度と入らないようにする。

## 過去の履歴

文書を直しても、前のコミットには元の文が残る。履歴の書き換えは取り消せないので、利用者が決めたときだけ行う。
