# 道具としての配り方（Release の計画）

ライセンスは非公開（社内・個人用、2026-10-12 決定）。使える人を限り、ソースは公開しない。

## 今の作りの事実（配り方を決める前提）

| 事実 | 影響 |
|---|---|
| 起動は `sh app/start.sh`。Windows ではそのまま動かない（WSL が要る） | 入口を Python のコマンドにすれば OS を問わなくなる |
| GPU の使い分けが無い。GPU のある PC でも CPU で描く（1 枚 約 5 分） | 配る前に GPU（CUDA、Apple の MPS）を自動で使う作りが要る。外部の生成の速さ（数十秒）に近づく一番の手 |
| 部品とモデルをリポジトリの中の `.cache` に置く前提（ROOT/.cache） | 入れた場所と別の置き場所（利用者のキャッシュ）を選べる作りが要る |
| 重いモデル 約 9GB は同梱せず、初回に取る。リポジトリは 32MB（履歴 85MB） | 配布物は小さく保てる。モデルは各ライセンスの条件どおり利用者が取る |
| 使う人は2種類: 人（画面・コマンド）と AI（Claude から MCP・スキル・作画監督の担当） | 入口を人と AI の両方に用意する |

## 選択肢

| 配り方 | 入れる手間 | 人が使う | AI が使う | OS | GPU | 更新 | CI の費用 | 非公開で配れるか |
|---|---|---|---|---|---|---|---|---|
| A. 今のまま（clone して start.sh） | 中（Node・Python を自分で入れる） | 画面 | MCP を手で登録 | Linux・Mac | 使えない | git pull | 無し | 非公開リポジトリへの招待 |
| B. pip パッケージ＋コマンド | 小（`pip install` 1 行） | コマンドと画面 | MCP を 1 行で登録（`characterdesigner mcp`） | Linux・Mac・Windows | 入れる torch で決まる | 版を上げて入れ直す | Release の時だけ部品を作る（Linux 1 本、数分） | 非公開リポジトリの Release か git の URL から入れる |
| C. Docker イメージ | 小（Docker があれば） | 画面 | MCP はコンテナの外から繋ぐ手間 | Docker が動く所 | NVIDIA だけ、設定が要る。Mac の GPU は使えない | イメージを取り直す | イメージを作る時間が長い（数十分） | 非公開のコンテナ置き場（GHCR） |
| D. Claude Code のプラグイン | 小（マーケットプレイスから入れる） | — | スキル・作画監督の担当・MCP がまとめて入る | Claude Code が動く所 | B に従う | プラグインの版 | 無し | 非公開リポジトリをマーケットプレイスにできる |
| E. デスクトップのインストーラー | 最小（ダブルクリック） | 画面 | MCP は別に登録 | OS ごとに作る | OS ごとに作る | 自動更新を作る必要 | OS ごとに作る（Mac・Windows は単価が高い） | 配る相手に渡す |

## 推奨: B と D の二段

1. 本体を B（pip パッケージ）にする。入口は `characterdesigner` コマンド1つ
   - `characterdesigner serve`（画面とサーバー）、`characterdesigner mcp`（MCP サーバー）、`characterdesigner measure / learn / draw`
   - 置き場所は既定で利用者のキャッシュ（`~/.cache/characterdesigner`）、環境変数で替えられる
   - GPU を自動で使う（CUDA → MPS → CPU の順）
2. AI の入口を D（Claude Code のプラグイン）にする。作画監督（checker）などの担当、キャラクターデザインのスキル、MCP の登録をまとめて入れる。中身は B のコマンドを呼ぶだけ
   - 理由: 人も AI も同じ本体を使い、AI 側は入れるだけで道具と使い方の両方が揃う（道具があるのに使い方を知らない、を防ぐ）

C は画面だけをサーバーに置きたくなった時に足す。E は配る相手が増えてから考える（費用と手間が大きい）。

## Release までにやること（推奨の場合）

1. 置き場所を入れた場所から切り離す（ROOT/.cache をやめ、利用者のキャッシュと環境変数で決める）
2. GPU の自動選択（描く速さの一番の手）
3. `pyproject.toml` とコマンドの入口（serve、mcp、measure、learn、draw、setup）
4. 版の番号（0.1.0 から。変わった所を CHANGELOG.md に）
5. 使っている部品とモデルのライセンスの一覧（`docs/third-party.md`。描く模型の利用条件を含む）
6. まっさらな環境での通し確認（入れる → 起動 → 1 枚描く → 測る → 学ぶ）。Linux と Mac。Windows は確かめられないので確かめていないと書く
7. Claude Code のプラグインの雛形（担当・スキル・MCP の登録）
8. タグを打った時だけ部品を作って Release に置く CI（Linux 1 本）
